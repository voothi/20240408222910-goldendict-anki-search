## Implementation Details
We introduced a `deck_filter` key in `config.ini` to allow users to lock searches to a specific deck or hierarchy. 

### Analytics and Decisions
1.  **Purpose**: The primary goal is to allow users to limit the scope of their work to the current material (e.g., a specific book or chapter). In large databases, search results can be overwhelming. Filtering by deck allows users to retrieve context-specific meanings relevant only to the current session or material.
2.  **Wildcard Matching**: To support flexible deck naming (including the user's ZID-based system), the filter logic applies wildcards on both ends: `deck:"*VALUE*"`. This allows matching a deck like `Root::201100-en-common` by just using the ID `201100`.
2.  **Optional Prefix**: To simplify copy-pasting from other tools or logs, we allow the configuration value to optionally start with `deck:`. The script strips this prefix automatically.
3.  **Multi-line Values**: Given that deck paths can be extremely long, we verified and documented support for standard INI multi-line values (indented on subsequent lines). This improves readability in `config.ini`.

### Configuration Key
```ini
[Search]
deck_filter = 
    201100-en-common...
```
