# RFC 20260117224440: Release 1.50.2 - Multi-Sentence Range Search

## Staging
Release 1.50.2

## My Request

## Implementation Details

### Analytics
- **Efficiency in Reading**: The primary goal is to enable users to read significant portions of a book (paragraphs or multi-sentence fragments) in a **single search operation**. This eliminates the friction of making separate requests for every single sentence as the user progresses through a text.

- **Multi-Sentence Detection**: Automatic identification of wide-range queries that span across multiple sequential Anki cards.
- **Anchor Strategy**: To handle long queries while remaining robust to minor OCR/formatting errors, we identify "Start" and "End" anchors (configurable word length, default 4). These anchors are used to find the boundary cards in Anki.
- **Verification Requirement**: Simply finding cards between two anchors is not enough (it could find irrelevant cards). Reconstructed text from the retrieved range must be verified against the query for high precision.

- **Deck Scope**: In tiered deck structures (e.g., `Parent::01-Sub`), cards in a logical sequence might span sibling sub-decks. The search must be scoped to the common parent to find the full range.

### Decisions
1. **Aggressive Normalization**: To prevent verification failure due to hyphens, HTML tags, or punctuation differences, both the query and reconstructed text are reduced to pure alphanumeric lowercase strings.
2. **Containment Matching**: Changed from strict equality to "substring containment" (`Query in ReconstructedText`). This handles cases where a user selects a partial phrase but the cards contain the full context.
3. **Single-Card Optimization**: If both anchors point to the same card ID, the script short-circuits the range search and verifies locally, saving multiple API calls.
4. **Configuration**: Introduced `config.ini` to allow users to tune `anchor_length` and `separator_chars` (punctuation that forces an anchor boundary) without editing code.
5. **Sibling Deck Support**: Implemented `get_parent_deck` and parent-scoped queries to allow ranges spanning across different sub-decks under a shared parent.
